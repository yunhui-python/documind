# 项目是怎么跑起来的

> 这篇不讲算法，只讲"一台电脑上，这个项目到底在发生什么"。
> 看不懂代码不要紧，先把这张图装进脑子——**90% 的"我完全懵"都是缺这张图**。

---

## 一、三个角色，别混在一起

| 角色 | 是什么 | 比喻 |
| --- | --- | --- |
| **磁盘上的 `.py` 文件** | 静态文本，不运行就是一堆字 | 菜谱 |
| **运行中的 Python 进程** | 把代码读进内存、真正在干活的东西 | 厨师 |
| **浏览器** | 发请求、看结果的顾客 | 顾客 |

**核心认知：改了菜谱，厨师不会自动按新菜谱做菜。** 得让他重读一遍——这就是"重启服务"。

另一个核心认知：**顾客不会进厨房**。浏览器永远只能"发请求、收响应"，它碰不到你的数据库和文件。

## 二、启动命令，逐字拆开

```powershell
python -m uvicorn app.main:app --reload
```

| 这一段 | 意思 |
| --- | --- |
| `python` | 启动 Python 解释器 |
| `-m uvicorn` | 把 `uvicorn` 这个包当成程序运行 |
| `app.main:app` | 找到 `app/main.py`，取里面名叫 `app` 的对象 |
| `--reload` | 多起一个"监工"进程，盯着 `.py`，一改就重启厨师 |
| 可选 `--port 8001` | 换端口（8000 被占用时用） |

### 启动时，机器里实际发生的 6 件事

1. **import `app.main`** → 这个模块的顶层代码从头执行一遍
2. `load_dotenv(BASE_DIR / ".env")` → 读 `.env`，塞进环境变量
3. `create_app()` → 建 `Repository`（顺手 `mkdir data/`）、`init_schema()` 建表
4. 创建 `HashingEmbedder`、创建 `FastAPI` 实例
5. `@app.get(...)` / `@app.post(...)` 这些装饰器把函数登记进**路由表**
6. uvicorn 开始监听 8000 端口，进入"等请求"状态

### 你该看到的真实日志

```
INFO:     Started server process [26560]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
```

看到 `Application startup complete` = 厨师就位。**没看到这行，说明启动失败了，往上翻找红色 Traceback。**

## 三、一次请求的旅程

### 例：你在 `/docs` 点 Execute 搜索 "k1"

```
浏览器
  │ ①  POST /api/search   Body: {"query":"k1 参数","top_k":3}
  ▼
uvicorn                    收到字节 → 解析成 HTTP 请求（方法、路径、头、体）
  │ ②  拿"POST + /api/search"去路由表里查，查到 do_search
  ▼
FastAPI + Pydantic          ③ 先校验：query 不能空、top_k 必须在 1~20
  │                            不合格 → 立刻返回 422，你的函数根本不会被调用
  ▼
do_search()                 app/main.py      ④ 开始执行业务代码
  │
  ├─ embedder.embed_query() app/embeddings.py ⑤ "k1 参数" → 256 个浮点数
  │
  └─ search(repo, 向量)     app/retrieval.py  ⑥
        ├─ repo.fetch_chunks()  app/db.py    ⑦ 查 SQLite，取出所有块（文字 + 向量）
        └─ 逐块算余弦 → 排序 → 取前 K   ⑧
  ▼
FastAPI                     ⑨ 把返回的 dict 序列化成 JSON
  ▼
浏览器                      ⑩ 渲染结果
```

**调 bug 就是在①②③④⑤⑥⑦⑧⑨⑩里找"断在哪一环"。**

- 结果为空 → 可能断在 ⑦（库里没数据），也可能断在 ⑧（分数都太低）
- 返回 422 → 断在 ③（你 JSON 写错了），压根没进业务代码
- 返回 500 → 断在 ④~⑧（代码里抛异常了，去终端看 Traceback）
- 浏览器显示 `Failed to fetch` → 断在 ① 之前（服务根本没开）

### 例：上传文档

```
POST /api/documents  (multipart 文件)
  → 后缀检查（不是 .txt/.md → 415）
  → 大小检查（> 5MB → 413）
  → 解码 UTF-8（失败 → 400）
  → ingest()  →  split_text() 切块   app/chunking.py
              →  embed_documents()   app/embeddings.py
              →  add_document()      app/db.py（一个事务里写 documents + chunks）
  → 201 {"document_id":1,"chunks":2}
```

## 四、改代码之后发生了什么

你保存 `chunking.py` → 监工发现文件变了 → **杀掉旧进程 → 重新 import → 启动新进程**。

日志里会出现：

```
INFO:     Detected changes in 'app\chunking.py'. Reloading...
INFO:     Application startup complete.
```

### 重启会丢什么、不会丢什么

| 东西 | 重启后 | 为什么 |
| --- | --- | --- |
| 你上传的文档、文本块 | **还在** | 存在磁盘文件 `data/documind.db` 里 |
| 终端里的日志 | 清空 | 内存里的东西 |
| `app` 对象、`repo`、`embedder` | 重建 | 内存 |
| 浏览器页面 | 还在，但要刷新才能用新逻辑 | 浏览器有缓存 |

**"进程会死，磁盘不会死"——这是服务端开发最基本的世界观。**
这也是这个项目用 SQLite 而不是把文档塞进 Python 变量的原因。

> 注意：`.env` 改了**不会**触发 reload（监工只看 `.py`）。改完要么 Ctrl+C 重启，要么随便在某个 `.py` 里加个空行保存一下。

## 五、出问题按这个顺序查（背下来）

1. **终端有红色 Traceback 吗？** —— 有就看**最后一行**，那才是真正的错误
2. **服务活着吗？** —— 浏览器开 `http://127.0.0.1:8000/api/health`
3. **请求到服务器了吗？** —— 看终端有没有这行：
   `INFO: 127.0.0.1:xxxx - "POST /api/search HTTP/1.1" 200 OK`
   没有 → 请求压根没发出去（地址错、服务没开）
4. **改了代码没生效？** —— 看终端有没有 `Reloading...`
   **没有，八成是代码有语法错误导致 reload 失败，服务还跑着旧代码**（这是"我明明改了"最常见的原因）
5. 最后才怀疑业务逻辑

### 状态码对照

| 码 | 含义 | 谁给的 |
| --- | --- | --- |
| 200 | 成功 | 你的代码 |
| 201 | 创建成功 | 你的代码 |
| 400 | 内容有问题（编码错、PDF 解析失败） | 你的代码 |
| 404 | 找不到（删不存在的文档） | 你的代码 |
| 413 | 文件太大 | 你的代码 |
| 415 | 格式不支持 | 你的代码 |
| 422 | **请求参数格式错**（JSON 写坏、必填项没给） | FastAPI 自动返回 |
| 500 | 代码抛异常 | uvicorn 兜底 |
| （无状态码）`Failed to fetch` | **根本没连上** | 浏览器 |

## 六、三个动手实验（今晚 20 分钟，每个都能立刻看到效果）

### 实验 1：让代码"说话"，确认请求真的走到了

打开 `app/main.py`，找到 `do_search` 函数，在它第一行加一句：

```python
    def do_search(payload: SearchIn) -> dict:
        print("我收到查询了：", payload.query)      # ← 加这行，注意缩进 8 个空格
        hits = search(
```

保存 → 看终端有没有 `Reloading...` → 去 `/docs` 搜一次 → **终端应该打印出你搜的词**。

看到那行字，你就亲手打通了"浏览器 → 服务器 → 你的代码"这条链。改完记得删掉这行。

### 实验 2：改配置，看行为变化

1. 打开 `.env`，把 `DOCUMIND_CHUNK_SIZE=500` 改成 `DOCUMIND_CHUNK_SIZE=150`
2. 重启服务（`.env` 不触发 reload）
3. 重新上传 `examples/03-RAG工程实践.md`，看返回的 `chunks` 是几
4. 再改回 500，重启，再传一次，对比块数

**这一实验说明：配置是从 `.env` 读进来的，读进来之后贯穿整个流程。**（记得把库清掉，否则会有一堆重复文档：删掉 `data/documind.db` 再重启。）

### 实验 3：让测试保护你

打开 `app/chunking.py`，故意把 `overlap` 的判断改坏，比如把

```python
    if overlap < 0 or overlap >= size:
```
改成
```python
    if overlap < 0:
```

然后跑 `python -m pytest`，看它红给你看。看完改回来。

**这就是测试的意义：它不是你写的"作业"，是拦住你的护栏。**

## 七、术语表（看文档、看报错时会遇到）

| 词 | 一句话 |
| --- | --- |
| **进程** | 内存里正在运行的程序。`uvicorn` 就是一个进程 |
| **端口** | 一台电脑上区分不同服务的编号。你的服务占了 8000 |
| **路由** | "哪个 URL 交给哪个函数处理"的对应表 |
| **请求 / 响应** | 浏览器发出去的 / 服务器返回的 |
| **JSON** | 一种文本格式，长得像 Python 的字典 |
| **环境变量** | 操作系统里存的一批"键=值"，程序和 `.env` 都在往这里写 |
| **依赖** | 你的代码用到的别人写的包，列在 `pyproject.toml` 里 |
| **虚拟环境 `.venv`** | 这个项目专属的依赖仓库，跟系统 Python 隔离开 |
| **入口点** | `app.main:app` 里的那个 `app`，uvicorn 从它开始跑 |
| **端点 / endpoint** | 一个具体的 URL 路径，比如 `/api/search` |

## 八、每天的工作循环就 5 步

```
① 启动服务（窗口 A 挂着别关）
② 改一个文件，保存
③ 看终端有没有 Reloading，有没有报错
④ 去 /docs 或浏览器验证行为变了
⑤ 跑 pytest 确认没弄坏别的（窗口 B）
```

**这五步就是你未来三个月每一天的工作。** 熟练之后，你会发现自己不再"懵"，因为你知道了每一步该看哪里。
