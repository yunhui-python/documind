## 先看全局：数据怎么流动

只需要记住这一条链路，后面所有代码都是它的某个环节：

```
文件/文本
   │  ① 解码、清洗                         app/main.py 的手写 → app/chunking.normalize()
   ▼
切块（每块 ≤ 500 字，块间重叠 80 字）       app/chunking.split_text()
   │  ②
   ▼
向量化（一段文字 → 256 个浮点数）           app/embeddings.HashingEmbedder
   │  ③
   ▼
存进 SQLite（documents 表 + chunks 表）    app/db.Repository
   │  ④
   ▼
【查询】问题 → 向量化 → 和每个块算相似度 → 排序取前 K   app/retrieval.search()
```

**读任何一段代码前，先问自己"它在①②③④的哪一步"。** 答不上来就说明还没读懂。

## 逐文件精读

### 1. `app/config.py` —— 10 分钟

- 先看 `Settings` 这个 dataclass，再看 `load_settings()`。
- **要能回答**：如果我在 `.env` 里写了 `DOCUMIND_CHUNK_SIZE=abc`，程序启动时会发生什么？
  （答案：`_env_int` 抛 `ValueError`，服务起不来。这是故意的——配置错了要立刻炸，不要默默用默认值。）
- **常见误解**：以为 `.env` 会自动生效。Python 不会自动读 `.env`，这个项目其实是读**环境变量**，
  `.env` 只是给你参考的模板。要真加载 `.env` 得装 `python-dotenv`（项目里已经装了，Week 2 会接上）。

### 2. `app/chunking.py` —— 40 分钟，**最重要**

按 `normalize → _split_long_paragraph → split_text` 的顺序读。

- 重点盯住 `split_text` 里第二步的这段：
  ```python
  seed = buffer[-overlap:].lstrip() if overlap else ""
  buffer = f"{seed}\n\n{unit}" if seed else unit
  ```
  **要能回答**：`buffer[-80:]` 取的是什么？为什么下一块要带着前一块的尾巴开头？
  如果 `buffer` 只有 30 个字、`overlap` 是 80 会怎样？（切片不会报错，会返回全部 30 个字。）
- **要能回答**：`if len(buffer) > size: buffer = unit` 这一行在防什么？
  （防"种子 + 新段落"拼起来超过块长上限。宁可丢掉重叠，也不能让块超长。）
- **常见误解**：以为切出来的是"句子"。不是，是"段落攒到差不多 500 字"，所以块边界可能在段落中间。

### 3. `app/embeddings.py` —— 30 分钟

- 先看 `tokenize`，再看 `_vectorize` 的 for 循环。
- **要能回答**：中文为什么要切成"单字 + 双字"？
  （单字区分度太低——"的""是"到处都是；双字不需要词典就能表达词组，是中文检索最便宜的基线。）
- **要能回答**：`sign = 1.0 if digest[4] & 1 else -1.0` 这一行，如果不写（全用 +1）会怎样？
  （不同词哈希到同一个下标时会一直累加，向量越来越"糊"；正负号让碰撞互相抵消。）
- **常见误解**：以为这 256 维向量有"语义"。它没有，它只有**字面重合**。
  这就是为什么"怎么防止模型胡说八道"搜不到讲幻觉的那篇。

### 4. `app/retrieval.py` —— 20 分钟

- 先看 `pack` / `unpack`，再看 `search`。
- **要能回答**：为什么用 `array("f")` 而不是 `json.dumps`？省多少？
  （float32 二进制，4 字节一个数；JSON 文本一个数要 10 字节以上，还慢。）
- **要能回答**：`if len(vector) != len(query_vector): continue` 这行在防什么事故？
  （换了 embedding 模型但没重建索引——维度对不上。跳过比算出垃圾分数好。）
- **常见误解**：以为向量库里有什么魔法。没有，就是**一个 for 循环 + 一次排序**，纯暴力。

### 5. `app/db.py` —— 30 分钟

- 先看 `SCHEMA`，再逐个看 `Repository` 的方法。
- **要能回答**：为什么 `connection()` 是个 `@contextmanager`，而不是直接把 `conn` 存成 `self.conn`？
  （sqlite3 的连接默认不能跨线程用，FastAPI 每个请求可能在不同线程；每次开新连接最安全。）
- **要能回答**：`PRAGMA foreign_keys = ON` 不加会怎样？
  （删文档时 `chunks` 表里的块会残留成孤儿数据，越积越多。）
- **常见误解**：以为 SQLite"不能用于生产"。单机、读多写少完全够用；瓶颈在"多实例部署"而不在 SQLite 本身。

### 6. `app/main.py` —— 40 分钟

- 先看 `create_app` 里最上面那几行（建 repo、建 embedder），再看 `ingest`，最后看路由。
- **要能回答**：为什么写成 `create_app(settings)` 工厂函数，而不是模块级 `app = FastAPI()`？
  （测试时能塞一个临时数据库进去，不污染你本地的 `data/documind.db`。看 `tests/conftest.py` 就明白了。）
- **要能回答**：`ALLOWED_SUFFIXES` 检查、大小检查、编码检查，这三道关分别防什么？
- **常见误解**：以为路由函数里的 `repo`、`embedder` 是全局变量。它们是闭包捕获的局部变量。

### 7. `tests/` —— 30 分钟

- 先看 `conftest.py` 的 `client` fixture，再看 `test_api.py` 里那个最长的测试。
- **要能回答**：`test_search_ranks_relevant_document_first` 为什么比"返回 200"值钱一百倍？
  （它断言的是**排序结果**，也就是业务正确性；200 只证明进程没崩。）

## 读代码的方法（比这次读什么更重要）

- **不要从第 1 行读到第 1000 行**。从一个入口出发，顺藤摸瓜：`/docs` 里发一次请求 →
  找到对应路由 → 跟到它调用的函数 → 再跟下一层。
- **PyCharm 三个快捷键**：`Ctrl+B` 跳到定义、`Ctrl+F12` 看当前文件所有函数、
  `Ctrl+Shift+F` 全局搜字符串（比如搜 `split_text` 看谁在调它）。
- **断点比 print 好用**：在 `split_text` 最后一行打个红点，跑一次测试，
  单步走一遍，看 `buffer` 和 `chunks` 怎么变。花 5 分钟，胜过读半小时。
- **看不懂的先跳过**，记到 `NOTES.md`，攒着一次问。卡在一个装饰器上两小时是最亏的。

## 附：`chunking.py` 变量词典

### 四个词代表四个粒度，别混

| 词 | 是什么 | 举例 |
| --- | --- | --- |
| `text` | 整篇文档，从文件读进来的一整串字符 | `"第一段…\n\n第二段…"` |
| `paragraph` | 一个自然段（空行分隔出来的） | `"第一段…"` |
| `unit` | 切块的**最小单位**：普通段落就是它自己；超长段落被滑窗切片后，每一片也算一个 | `"第一段…"` 或 超长段的第 0–500 字 |
| `chunk` | **最终产物**，一个块，由 1~N 个 unit 拼成 | `"unit1\n\nunit2"` |

为什么 `unit` 和 `chunk` 要分开：一个段落可能太长装不进块（得切开），也可能太短（得和别人拼），
所以"段落"和"块"不是一一对应的。

### 装行李箱的比喻

| 变量 | 比喻 | 类型 |
| --- | --- | --- |
| `units` | 摊在床上的一件件衣服（待装箱） | `list[str]` |
| `buffer` | **正在装的那个箱子**（核心状态） | `str` |
| `chunks` | 已经封好、码在旁边的箱子 | `list[str]` |
| `seed` | 从上一个箱子挑出来、塞进新箱子的那件衣服（防止搭配被拆开） | `str` |

### 逐个说明

| 变量 | 出现位置 | 作用 | 会不会变 |
| --- | --- | --- | --- |
| `DEFAULT_SIZE` / `DEFAULT_OVERLAP` | 模块顶部 | 默认块长 500、默认重叠 80 | 常量，永不改 |
| `text` | 各函数参数 | 输入文本 | `normalize` 里被反复重新赋值（先替换换行、再压缩空格），最终返回处理后的结果 |
| `size` | 各函数参数 | 每块最多多少字 | 只读 |
| `overlap` | 各函数参数 | 相邻块重叠多少字 | 只读 |
| `step` | `_split_long_paragraph` | 窗口每次前进多少 = `size - overlap` | 循环前算一次 |
| `start` | `_split_long_paragraph` | 当前窗口的起点（0, 420, 840…） | 每轮 `+= step` |
| `parts` | `_split_long_paragraph` | 切出来的碎片 | 只增不减 |
| `units` | `split_text` | 第一步的产物：所有最小单元 | 只增不减 |
| `paragraph` | `split_text` 的第一个 for | 循环变量，当前这一段 | 每轮换一个 |
| `buffer` | `split_text` 第二步 | **正在装的这一块**，全函数最重要的状态 | 每轮可能被改、被清空、被重置 |
| `unit` | `split_text` 的第二个 for | 循环变量，当前要装进去的单元 | 每轮换一个 |
| `chunks` | `split_text` | 已经封好的块，最终返回它 | 只增不减 |
| `seed` | `split_text` | 下一块开头要塞进去的"前一块尾巴" | 每次封块时重算 |

### 读任何循环前，先问三件事

1. **哪些变量在循环里被改？**（这里：`buffer`、`chunks`、`unit`、`paragraph`）
2. **它们是往哪个方向改？**（`chunks` 只增；`buffer` 忽长忽短）
3. **循环什么时候停？**（`units` 遍历完；`start` 超过文本长度）

把这三个问题答出来，95% 的循环你都能看懂，不用逐行念。
